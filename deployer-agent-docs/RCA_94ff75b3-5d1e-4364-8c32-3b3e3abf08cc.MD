# RCA — Login imposible en producción (didiershop.live): admin del tenant borrado

## Síntoma
`POST /api/auth/login` con `{identifier: "didiershop", password: "Didier2026$"}` responde **401 "Credenciales inválidas"**. Ningún usuario del tenant puede entrar.

## Causa raíz (PROBADA)
El endpoint `POST /api/admin/cleanup-database` (backend/server.py:11572) borró la colección `users` del tenant **incluyendo al propio admin**.

Código ofensor (server.py ~11600):
```python
for collection_name in collections_to_clean:   # incluye "users"
    result = await collection.delete_many({"tenant_id": tenant_id})
```
`collections_to_clean` incluye `"users"` y el filtro es solo `{"tenant_id": tenant_id}` — **no excluye `role:"admin"`**, así que elimina al administrador junto con los clientes.

- `audit_logs` conserva el evento del borrado (se escribió DESPUÉS del delete, por eso sobrevivió):
  - `action: "database_cleanup"`, `total_deleted: 209`, `created_at: 2026-10-14T13:15:54Z`
  - `user_id: 8f56430e-ec5e-4550-81b0-e57004833d1b`, `user_name: "Admin"`, `user_role: "admin"` → **id original del admin recuperado**.
- Lógica de login (server.py:1319): con `identifier = "didiershop"` busca el tenant por `slug`, luego `db.users.find_one({tenant_id, role:"admin"})`. Al no existir, cae a 401.
